二、这轮测试修掉的 6 个真实缺陷第一轮跑完是 7/14，全部是"看起来无害"的坑

①每条群通知都中招：@所有人 被识别成地点

修之前地点 = 所有人（N03 / N08 / N10 三条全错）
修之后地点 = 空；@所有人 / @全体成员 一律当圈人标记剔除

②「活动时间」里的「时」被当成时间残渣删掉，标题出现空洞

修之前活动 间: 晚 -22、平 看剧的 候（"时间"→"间"、"时候"→"候"）
修之后只在前一个字符是空格/数字时才吃残留的「时/点」，且躲开「时间/时候/时光/时段」

③长通告的标题直接等于整段正文

修之前📢【 光机·首届“名场面”仿拍大赏来啦！】🎬 平 看剧的 候，是不是总有几个
修之后① 开头 【】 里的中文标题优先 → 「时光机·首届“名场面”仿拍大赏来啦」；② 无角标时取首个带"活动/会议/培训/提交"这类事件词的句子，跳过宣传口号

④10.19 24:00 整条被丢弃（作业 ddl 提醒直接没了）

修之前没有日期也没有时间 → 解析结果 null，作业 ddl 建不出日程
修之后支持点分日期 10.19；24:00 规范化为当天 23:59

⑤11-12月（月份区间）被当成 11月12日

修之前日期 = 11-12，把「今晚20:00」的 ddl 顶掉了
修之后短横线后跟「月」的按月份区间处理，日期回退到「今晚」→ 10-23 20:00

⑥地点解析两处漏：托辞当地点、地点尾巴带动作词

修之前另行通知（N07）、具体地点后续在群里通知（N01）、知识产权楼321开展（N12）
修之后含「通知/后续/待定/另行/群里」的候选一律否决；动作尾巴（开展/举办/培训/集合…）剥掉；📍X 图标定位单独支持

三、回归测试怎么留

这 14 条语料已经写成 JUnit 用例 NotificationCorpusTest.kt 放进工程， 和原有 15 条规则用例一起跑： 

./gradlew testDebugUnitTest
# DateTimeParserTest      15 tests  0 failed
# NotificationCorpusTest  14 tests  0 failed

基准时间固定为 2026-10-23 14:50（周五），否则「明天/下周三/本周日」这类相对表达没有稳定期望值。

四、这次没变的限制不是 bug，是当前设计的边界

  • 起止区间只取起点：「10月16日—10月26日」记 10-16，「19:00-22:30」记 19:00。截止日要靠同段话里单独的「10月26日前」那句。
  • 一段话多个日期只取第一个：活动周期 + 报名截止混在一段的公告，需要在预览里确认取的是哪个。
  • 只有「下午/晚上」没有钟点：存全天，置信度 55，不瞎猜钟点。
  • N06 这类纯元信息行没有真标题：整行只有「活动时间：10月16日—10月26日」，标题只能回退成原文片段。
