先说清楚：哪些数据本来就该留、哪些不该留

「不要保存用户数据」在日程应用里有两种解读，必须分开处理： 日程本身必须存（不存这个应用就没有意义）；但为了排查而顺手存下来的东西，一条都不该留。 审查前的问题是后者：抓取日志把每条通知的原文都写进了 SharedPreferences。

数据存在哪加密能否关/删会不会外传
日程（标题/时间/地点/原文摘要） 本机 SQLite schedule.db 否（应用私有目录） 可一键全删 不外传
通知处理日志（应用名/结果/原因） SharedPreferences 否 可清空 不外传
通知原文 日志 / 日程备注 否 日志里默认不存（新增开关）；备注截断 500 字 不外传

通知原文（发给大模型时） 不落盘 — 默认不允许，需显式开启 会发给第三方，仅在用户开启后

这次改了什么

1. API Key 不再明文落盘

原来直接 putString("llm_key", 明文)。SharedPreferences 是私有目录里的明文 XML， root 设备、调试版、任何能把 /data/data 拿出来的手段都能直接读到 —— 而 API Key 是用户的付费凭证。

  • 改用 Android Keystore 生成不可导出的 AES 密钥，密钥留在 TEE 里，应用只能请求加解密
  • 密文用 AES/GCM（带认证标签，改一个 bit 就解不开）
  • 老版本存过的明文条目，第一次读取时自动迁移并删除
  • 解密失败（换机、Keystore 重置）当作"未配置"，不会崩

2. 关掉所有能整体搬走数据的路

  • allowBackup=false —— 原来默认 true，adb backup 一条命令就能把数据库 + 全部设置导出
  • fullBackupContent=false —— 覆盖 API 30 以下
  • data_extraction_rules.xml —— 覆盖 API 31+，云备份和换机迁移都排除全部数据

3. 禁止明文 HTTP

原来 usesCleartextTraffic=true。用户可以把大模型地址填成 http://， 那么通知原文和 API Key 会以明文走网络，同一 Wi-Fi 下抓包就能拿到。

  • usesCleartextTraffic=false + network_security_config，只对 localhost / 127.0.0.1 / 10.0.2.2 放行（方便自建本地服务调试）
  • 代码层提前拦截并提示，免得用户填了 http 只看到"识别失败"却不知道为什么

4. 通知原文不再默认写进日志

抓取日志原来存每条通知的前 160 字。那条"为了排查"的理由很正当，但代价是把 聊天内容、验证码、订单号长期留在本机。现在：

  • 日志只记「哪个应用 / 什么结果 / 为什么」，默认不含正文
  • 需要排查时，设置里可以开「记录通知原文」，只留 80 字，随时能关
  • 日程备注里的原文截断到 500 字

5. 通知自动抓取不再默认把内容发给大模型

原来只要开了大模型，每一条本地解析失败的通知都会被原文发到第三方接口 —— 用户以为自己只开了"手动识别"，实际后台一直在外传。现在拆成两个开关：

  • 大模型总开关（管手动「识别」按钮）
  • 「通知自动抓取时调用大模型」默认关闭，要让后台也联网必须专门打开

6. 锁屏不再显示日程内容

提醒通知原来是明文的，锁屏上直接显示「复诊」「面试」「交房租」这类标题。 现在设为 VISIBILITY_PRIVATE + 脱敏的 PublicVersion： 锁屏只显示"智能日程 · 日程提醒"，解锁后才看得到具体内容。

7. 收掉多余的对外入口

组件导出说明
MainActivity是桌面入口，必须导出；无入参、无敏感返回
SettingsActivity / CaptureLogActivity否—
NotificationCaptureService否额外受 BIND_NOTIFICATION_LISTENER_SERVICE 保护

还剩什么风险（不粉饰）

1. 这是 debug 签名包，android:debuggable=true。 自己用没问题；如果要分发给别人，必须出 release 包并自签名，否则调试器可以附加到进程读内存。
  • FLAG_SECURE 只在后台生效（v1.6 已加）：切到后台时窗口上锁，最近任务缩略图变空白；回到前台自动放开，正常截图、录屏、分享不受影响。实现见 util/ScreenGuard.kt，挂在 ActivityLifecycleCallbacks 上统一处理。挡不住另一台手机对着屏幕拍，以及 root 后直接抓显存。
  • root 设备：SQLite 明文存储对 root 无防护。Android 上单应用无法对抗 root。
  • 大模型服务商本身：开启后原文会发给对方，是否留存在他们那边由对方政策决定。这是使用该功能的固有代价。
  • Keystore 在恢复出厂后失效：旧密文解不开，表现为"Key 需要重填"，属预期行为。
自己验证（可选）：
aapt2 dump badging app-debug.apk | grep -i backup 应无输出；
adb shell dumpsys package com.terry.smartschedule | grep -i exported 查看导出组件；
设置里点「删除所有本地数据」，再检查 adb shell run-as com.terry.smartschedule ls -l databases shared_prefs。
