智能日程 v1.1 修复报告

针对真机试用反馈的三个问题：识别不到 / 日期错还照生成 / 顶部压状态栏

单测 29/29 通过 lint 0 error 日期场景 12/12 通过 APK 已重编 6.8 MB
一句话结论：三个问题都不是"偶发 bug"，是设计缺陷。识别不出的根因是静默丢弃——应用明明收到了通知却什么都不做，也不留痕； 日期问题的根因是解析器把"推算"当成了"事实"，而且没有任何字段能把"我拿不准"这个信息传给界面； UI 压状态栏的根因是 targetSdk=35 在 Android 15 上强制 edge-to-edge，android:statusBarColor 已经失效。

问题 1：自动添加"有时候识别不到"，后台没保活

拆开看是四个独立缺陷，加一起就是"通知来了，应用没反应，也说不清为什么"。

缺陷上一版的代码现在

粗筛挡路 前置筛选要求文本含「点时日月周分号」，明天开会 这类纯中文相对时间全被丢掉 放宽：有数字 / 有时间信号 / 有日程类词（开会、提交、截止…）任一就放行
去重误伤 SharedPreferences 只存"最后一条签名"，被后续通知覆盖后同一条又重复处理，反之也可能永久漏掉 内存 LRU（32 条）+ 10 分钟窗口，不落盘

保活：四层，但先说实话

Android 上没有"绝对保活"。能不能常驻最终由系统内存策略和厂商 ROM 决定，代码顶不住。 上一版是"N 层都不做"，现在是"N 层都做，把概率拉到最高"。
手段作用位置
前台服务进程优先级从"可随意回收"抬到"前台级"，通知栏占一行（可关）KeepAliveService

电池优化白名单国产 ROM 上最关键的一步，不对其豁免就随时被冻结设置页一键申请
自启动引导按小米/华为/OPPO/vivo/三星/魅族逐个试跳对应管理页，跳不进给文字路径ServiceHealth.openAutoStartSettings

新增：通知处理日志

这条最实用。"识别不到"没法排查，是因为之前什么都没记。现在每条像日程的通知都会留一条记录，并写明结果和原因：

  • 已建日程 识别成功并入日程
  • 待确认 识别出来了但没把握，原因是具体哪一处
  • 已跳过 收到了但没建，原因如"没识别出日期时间""已经有一条一样的""10 分钟内重复"

入口：设置 → 查看最近的通知处理记录（保留最近 40 条）。

主界面副标题直接显示状态

之前只能看"授没授权"，看不出"服务到底活没活"。现在分三种：

  • 通知监听未授权 · 点右上角去开启
  • 通知监听运行中，识别到日程自动记录
  • 通知监听已断开 · 点右上角修复

问题 2：日期识别错了却照样生成

新原则：能推算的要标明是推算的，算错了要报出来，拿不准的一律不许自动入库。

解析结果新增两个字段：dateSource（日期从哪来）和 warnings（需要你核对的问题）。 warnings 非空时置信度强制压到 70 以下，直接进"待确认"。

实测：12 个日期场景

基准时间固定 2026-10-23 14:50（周五）。"来源"列：ABS=原文写死，REL=明天/3天后，WEEK=周X 推算，TIME_ONLY=只有时间。

待确认怎么处理

待确认的日程：

  • 不排提醒（没确认的东西不该响）
  • 列表里置顶，橙色描边 + 「待确认」标签
  • 点一下弹出核对框：时间 + 为什么拿不准 + 原文节选，可选「确认添加 / 删除 / 取消」
  • 主界面顶部横幅显示「有 N 条识别结果待确认」

问题 3：顶部压状态栏 + 界面不好看

压状态栏的根因

targetSdk = 35。Android 15 起，targetSdk 35 的应用强制 edge-to-edge， 内容会被画到状态栏下面，而 android:statusBarColor 从这一版起完全失效。 上一版还在主题里设 statusBarColor——等于没设，所以顶部必然重叠。

正确修法：不要跟主题较劲，主动读 WindowInsets。

  • WindowCompat.setDecorFitsSystemWindows(window, false) —— 显式进入 edge-to-edge，让各版本行为一致
  • 头部塞一个 0dp 占位 View，代码里把高度设成 statusBars().top —— 渐变头部铺满到屏幕最顶，文字不被压
  • 列表底部加 navigationBars().bottom —— 最后一条不被手势条盖住

三个页面（主界面 / 设置 / 日志）统一走 util/Insets.kt。

本轮额外修掉的解析 bug

  • 「晚上7」这种省略"点"的写法时间没识别出来，残渣留在标题里 → 新增 RE_PERIOD_TIME，且不会把「下午3点半」截成 3 点
